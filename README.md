# 行程 App（PWA）

**线上地址（永久，不需要开发者的电脑开着）**

## 👉 https://stoneszy21.github.io/travel-plan/

iPhone 用 Safari 打开，然后「分享 → 添加到主屏幕」。打开过一次之后，**断网也能用**（Service Worker 缓存）。

---

给自己用的旅行计划工具：按天时间轴、地图点位、日出日落与月相。纯静态站点，无后端、无账号、无第三方依赖。

当前数据是**真实行程**：2026-11-13 上海出发，底特律转机到劳德代尔堡，先玩奥兰多（含肯尼迪航天中心一日的详细流程），11/17 回到劳德代尔堡参加 **WAF 2026（11/18–11/20，Broward County Convention Center）**，11/22 飞回上海。共 10 天。

## 怎么更新内容

**说一句话就行**：告诉助手要改什么，助手改完执行推送，约 1 分钟后线上生效，手机上刷新即可。

自己动手也行：

1. 编辑 `trip-data.js`（格式见下）
2. 双击 `deploy.cmd`（或命令行 `.\deploy.ps1 "改了箱根的晚餐"`）
3. 等 1 分钟，手机上刷新

> 推送需要能连 GitHub（国内直连不稳定），`deploy.ps1` 会自动读取系统代理设置；没开梯子时推送会失败，但**代码改动不会丢**，开梯子后重跑即可。

## 改行程

只改 `trip-data.js`：

```js
window.TRIP = {
  title: '东京 · 箱根',
  subtitle: '第一次东京 + 富士山，2 人，7 天',
  timezone: 'Asia/Tokyo',        // 日出日落/月相按这个时区算
  people: 2,
  days: [{
    date: '2026-11-14',
    title: '抵达东京 · 新宿',
    area: '新宿',
    base: { lat: 35.6938, lng: 139.7034 },   // 算日出日落用的坐标（填当天住宿点即可）
    note: '长途飞行，别安排太满',
    items: [{
      time: '14:30',            // 到达时间（当地时间，HH:mm）
      name: '成田机场 T1 入境',
      type: 'transport',        // transport / sight / food / stay / shop / other
      lat: 35.7719, lng: 140.3929,
      stay: 70,                 // 停留分钟
      transit: '飞机 3.5 小时',  // 从上一站怎么过来
      note: '提前填好 Visit Japan Web'
    }]
  }]
};
```

注意点：

- `lat` / `lng` 是小数度，北纬东经为正。Google 地图里右键点位置能复制「35.7719, 140.3929」这种格式，**纬度在前**。
- 不加坐标的点位只会出现在时间轴里，不会出现在地图上。
- `time` 只是显示用的字符串，不会自动校验先后顺序。

## 现在能做什么

| 功能 | 状态 |
|---|---|
| 总览页：日历卡样式，一屏看完十天主题，点一天跳到当天 | ✅ |
| 按天时间轴（时间/停留/交通/备注），吸顶日期条随滚动高亮 | ✅ |
| 打勾标记「已去过」（存手机本地，关页面不丢），也可当待办清单用 | ✅ |
| 同一天可并列「方案 A / 方案 B」，时间轴上用分隔条分开 | ✅ |
| 复制当天行程成文字，直接发微信 | ✅ |
| 真地图（OSM 底图，可拖拽/双指缩放）、按天连线、切单日看顺序、跳 Google 地图导航 | ✅ |
| 每天日出/日落/黄金/蓝调/月升/月落/月相 + **天气**（16 天内是预报，更远用去年同期） | ✅ |
| 分类页：洲际交通 / 当地交通 / 景点（营业时间、园内动线、景点图标） | ✅ |
| 交通距离：自驾/打车取 OSRM 实际路线，步行/公交为直线距离 | ✅ |
| 天文总览（横向对比选观测点） | ✅ |
| 离线打开（连过网之后） | ✅ |
| 账号、多用户、多人协作 | ❌ 还没做，当前是只读单份数据 |

距离数据来自 [OSRM](https://project-osrm.org/) 公共路由服务（免费、免 Key），取不到时退化为直线距离。天气数据来自 [Open-Meteo](https://open-meteo.com/)（免费、免 Key）。16 天以内是预报，超出的日期用去年同期的实测值做参考，界面上会标「预报」或「去年同期」。结果缓存 3 小时。

## 已知限制

- **地图底图需要联网**（OpenStreetMap 瓦片），断网时只显示点位和连线；连线是直线，不代表实际路线，真实路线用点位弹层里的「在 Google 地图打开 / 导航到这里」。
- **没有后台提醒**：iOS 的 PWA 拿不到后台定位和定时通知，只能做到"打开页面时看到"。
- **国内访问 GitHub Pages 不稳定**，需要梯子；出境后正常。
- 日/月计算是本地算法：日出日落误差约 1 分钟，月升月落误差几分钟。

## 技术说明

- `index.html` 单文件：结构 + 样式 + 逻辑，无任何第三方库、无 CDN、无 API Key
- 日月计算是内联的天文算法（太阳用 SunCalc 风格公式，月球带主要摄动项），时区用 `Intl` 处理
- 地图是自写的 Web Mercator 瓦片渲染（OSM 底图 + 拖拽/双指缩放/双击放大），不依赖任何地图库
- Service Worker 用**网络优先 + 断网回落**，保证更新能立刻生效

## 开发自检

```powershell
node tools/check-static.js             # 语法 / id / class 一致性
node tools/check-astro.js              # 跑 App 自己的天文算法 + 不变式检查
python tools/check-sun-noaa.py         # 与 NOAA 公式交叉验证日出日落
python tools/check-moon-schlyter.py    # 与 Schlyter 模型交叉验证月升月落
python tools/make-icons.py             # 重新生成图标
```

最近一次结果（2026-11 佛罗里达行程）：日出日落与 NOAA 最大偏差 1 分钟，月升月落与 Schlyter 模型最大偏差 11 分钟（参考实现用固定视差，App 用动态视差，实际更准）。
