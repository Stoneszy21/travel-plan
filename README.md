# 行程 App（PWA 原型 v0.1）

给自己用的旅行计划工具：按天时间轴、地图点位、日出日落与月相。纯静态站点，无后端、无账号、无第三方依赖。

**当前数据是示例行程**（东京 + 箱根，2026-11-14 → 11-20，2 人，47 个点位），换成真实行程只需改 `trip-data.js`。

---

## 手机上怎么打开

### 1. 电脑上启动一个静态服务

在资源管理器里右键 `start-server.ps1` → **使用 PowerShell 运行**（或命令行执行 `.\start-server.ps1`）。

脚本会打印两个地址，例如：

```
本机：http://127.0.0.1:8080
手机：http://192.168.31.165:8080
```

### 2. iPhone 上打开

1. 确认 iPhone 和电脑连的是**同一个 WiFi**
2. Safari 打开脚本打印的「手机」地址
3. 分享 → **添加到主屏幕**，之后从桌面图标进，全屏无地址栏

> 局域网地址是电脑的内网 IP，换了 WiFi 就会变；到时候重跑脚本看新地址。

### 打不开怎么办

Windows 默认把 WiFi 判定成「公用网络」，会**拒绝所有入站连接**，手机就连不上。这台机器已经加过规则了；如果换了新 WiFi 后又打不开：

1. 双击 `allow-firewall.cmd`，UAC 弹窗点「是」（只放行本网段访问 8080，公共 WiFi 上的陌生人连不进来）
2. 确认 iPhone 的 IP 和电脑同网段（设置 → 无线局域网 → ⓘ → IP 地址，应和电脑都是 `192.168.31.x`）
3. 还不行就在 iPhone 上打开 `http://192.168.31.1`（路由器后台）：
   - 能打开 → 局域网是通的，问题在电脑侧
   - 打不开 → 路由器开了「AP 隔离」或手机不在这个网

## 改行程

只改 `trip-data.js`，存盘后在手机上刷新即可。

```js
window.TRIP = {
  title: '东京 · 箱根',
  subtitle: '第一次东京 + 富士山，2 人，7 天',
  timezone: 'Asia/Tokyo',        // 日出日落/月相按这个时区算
  people: 2,
  days: [{
    date: '2026-11-14',
    title: '抵达东京 · 新宿',
    area: '新宿',
    base: { lat: 35.6938, lng: 139.7034 },   // 算日出日落用的坐标（填当天住宿点即可）
    note: '长途飞行，别安排太满',
    items: [{
      time: '14:30',            // 到达时间（当地时间，HH:mm）
      name: '成田机场 T1 入境',
      type: 'transport',        // transport / sight / food / stay / shop / other
      lat: 35.7719, lng: 140.3929,
      stay: 70,                 // 停留分钟
      transit: '飞机 3.5 小时',  // 从上一站怎么过来
      note: '提前填好 Visit Japan Web'
    }]
  }]
};
```

注意点：

- `lat` / `lng` 是小数度，北纬东经为正。Google 地图里右键点位置就能复制「35.7719, 140.3929」这种格式，纬度在前。
- 不加坐标的点位只会出现在时间轴里，不会出现在地图上。
- `time` 只是显示用的字符串，不会自动校验顺序。

## 现在能做什么

| 功能 | 状态 | 说明 |
|---|---|---|
| 按天时间轴（时间/停留/交通/备注） | ✅ | 吸顶日期条，滚动自动高亮当天 |
| 打勾标记「已去过」 | ✅ | 存在手机本地（localStorage），关页面不丢 |
| 复制当天行程成文字 | ✅ | 一天一个「复制」按钮，可直接发微信 |
| 地图打点、按天连线 | ✅ | 免 API Key 的示意地图，按地理比例投影；点选某天看当天顺序和路线 |
| 跳 Google 地图 | ✅ | 点位弹层里「在 Google 地图打开 / 导航到这里」；选某天后可一键导航当天路线 |
| 每天日出/日落/黄金/蓝调/月升/月落/月相 | ✅ | 本地算法，不联网 |
| 天文总览页 | ✅ | 每天一张卡，横向对比选观测点 |

## 已知限制

- **地图是示意图**，不是真实路网，直线连接不代表实际路线。用 Google 地图看真实路线（点位弹层里的按钮）。
- **离线要 https**：Service Worker 只在 https / localhost 下生效。局域网 http 访问时页面能用但没有离线缓存；要真正离线，得把这个文件夹托管到 https 站点（GitHub Pages / Cloudflare Pages 都免费）。
- **没有后台提醒**：iOS 的 PWA 拿不到后台定位和定时通知，只能做到"打开页面时看到"。
- 日出日落实测算过（见下），月升月落是简化算法，误差几分钟。

## 开发与自检

```powershell
# 语法 / id / class 一致性
node tools/check-static.js

# 跑 App 自己的天文算法，输出每天日月数据 + 不变式检查
node tools/check-astro.js

# 用另外两套独立算法交叉验证（需要 python）
python tools/check-sun-noaa.py         # NOAA 经典公式，逐日对比日出日落
python tools/check-moon-schlyter.py    # Schlyter 月球模型，逐日对比月升月落

# 重新生成图标
python tools/make-icons.py
```

最近一次结果：日出日落与 NOAA 最大偏差 1 分钟，月升月落与 Schlyter 最大偏差 7 分钟，正常。
